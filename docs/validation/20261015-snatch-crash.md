# 0.1.4 顺手牵羊空手牌崩溃

## 证据与结论

用户提供 2026-10-15 22:56 的 0.1.3/build4 ARM64 崩溃报告。游戏线程路径为 Snatch::onEffect → Room::askForCardChosen（旧第938行）→ ServerPlayer::getRandomHandCardId → getRandomHandCard。不复制含机器信息的完整报告到仓库。

已安装二进制与旧 dSYM 的 UUID 为 42D6F5F8-3627-3166-B2A7-3466A7B095B1。反汇编中，故障前从 handcards 读出数据指针 x10、长度 x9，然后计算随机数除以长度的余数，作为数组索引。报告 x9=0；x10=0x7572b2d48、x8=0x59182a6e，x10+8*x8 正好为故障地址 0xa1fec80b8。确认空手牌取随机牌造成越界，而不是主公身份本身的特殊规则。

旧第938行仅在选牌结果为 -1（隐藏手牌占位值）时进入；未检查目标是否仍有手牌。报告能确认崩溃机制，不能区分该结果来自当时客户端状态还是 AI/托管返回，也不能还原完整牌局；没有宣称已重放用户的原局。UI 原本已禁用本地显示为空的手牌按钮，服务端仍必须独立校验。

## 修复

- 随机手牌接口在空手牌时返回 nullptr/-1，避免除零和越界。
- askForCardChosen 在请求前及收到结果后核对实际可选区域；仅在允许手牌且确有手牌时解释 -1。
- 无效、过期、超时或越区域结果，从当前允许区域的牌中随机兜底；保留合法具体牌的选择。完全无牌返回 -1。
- 顺手牵羊和过河拆桥遇到无可选牌安全结束，不把 -1 当实际卡牌继续处理。
