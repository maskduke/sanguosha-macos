# 0.1.5 手牌同步根因与旧旋风 AI

## 崩溃上游：誓仇／眩惑的混合区域移动

0.1.4 已确认并保护“服务端空手时处理 -1 随机手牌选择”的崩溃点，但尚未解释为何客户端仍允许选择手牌。用户补充：主公为汉昭烈帝（bgm_liubei）＋旧凌统（noslingtong），记得界面显示还有一张手牌，并要求继续调查同步机制。

核对本版资源说明与 Snatch::targetFilter：顺手牵羊要求距离1、区域里有牌的其他角色，包括手牌／装备／判定区，不限定必须有手牌。客户端幻影手牌会让手牌按钮仍可点，而服务器手牌已为空。

已发现并确定复现的根因在 Room::moveCardTo。旧逻辑为不公开的整批牌仅发送一条 moveNCards，来源角色和区域全部由第一张子牌推断。誓仇和眩惑都是先把第一张牌放入私有暂存区，再把它与仍在手牌／装备区的第二张一起转移。

假设初始两张手牌：

1. 客户端显示2张。
2. 第一张进入暂存区，消息 `moveNCards 1:lord->lord@special`，客户端减到1张。
3. 旧消息 `moveNCards 2:lord@special->recipient` 把第二张也错误视为来自暂存区，漏减其手牌数。
4. 服务端实际两张都已移走，手牌0；旁观客户端残留1。后续正常摸牌／出牌仍会保留这个差额。

02-red.log 在真实眩惑技能、真实服务端消息、真实 Client::processReply 解析下复现客户端1 vs 服务端0。随后使用用户指定的 SP刘备＋旧凌统组合，调用真实誓仇 PhaseChange 分支，验证同一混合区域流程；修复后两端均为0，选牌窗口手牌按钮禁用。原局没有回放，因此这是与武将和症状高度吻合、且已确定存在的上游机制，不能宣称完整重放了用户当时的所有步骤。

修复按每张实际移动的牌计算来源、去向和可见范围，再通知客户端；不再从第一张子牌推断整批。隐藏手牌仍只向无查看权的人发送数量，公开装备／判定区则发送公开移动；保留整批 CardLostDone/CardGotDone 的触发时机。无效选牌防崩保护保留。

## 旧旋风：策略名称不匹配导致随机选人

NosXuanfeng C++ 请求 `xuanfeng-damage` / `xuanfeng-slash`，Lua 实际注册的是 `nosxuanfeng_damage` / `nosxuanfeng_slash`。Lua 将连字符替换为下划线后仍无法找到对应策略，进入 math.random 兜底，且对应的目标行为意图更新也无法匹配。

已将 C++ 请求改为 `nosxuanfeng-damage` / `nosxuanfeng-slash`，恢复原有敌友伤害／出杀策略与意图回调。AI使用其感知阵营，不读取隐藏身份作为作弊判断；没有重写整套战术策略。

06-skills-red.log：真实 C++技能 → LuaAI 选目标，在固定敌友感知、固定随机兜底为第一个友方的测试中，旧伤害与出杀均选 p1 友方。08-skills-green.log 以及最终测试中，两分支均选 p3 敌方。新增仅友方场景验证原策略选择不发动。
