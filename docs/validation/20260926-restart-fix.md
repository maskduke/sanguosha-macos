# 0.1.2 单机重复开局修复

用户路径：完成一局 → 回主界面 → 单机启动 → 确定，提示不能启动服务器。

根因：MainWindow 返回主界面仅删除 Client，上一局 Server 仍作为窗口子对象存活，继续监听原端口；新 Server 无法绑定同一端口。

修复：窗口明确记录单机专用 Server。返回主界面时先停止所有所属 Room/游戏线程，成功后销毁 Server 并释放端口，再清除 ClientInstance/Self 指针；停止超时保留对象并提示重试，避免删除运行中的线程。下次启动也做防御性清理；绑定失败立即删除新建 Server，配置对话框改为作用域管理。独立联机服务器不受单机清理影响。

证据在 `test-results/20260926-restart/`：

- RED：真实 MainWindow 单机启动/返回槽执行后，原 Server 未销毁（02-red.log）。
- GREEN：同一进程两次进入/返回；使用系统分配的固定空闲端口，房间存在时端口不能重绑，返回后立即可以重绑。
- 另一路径每轮用真实 Room 完成一局两人 AI 游戏后返回主界面，再次调用真实单机启动入口。此测试用自动 AI 替代人工出牌，未模拟人类完整操作序列。
- Debug / Release 10 组已实现代码回归通过；新增重复开局测试在 ASan 及原生 Cocoa 后端均通过。ASan 使用 detect_leaks=0，不宣称没有内存泄漏。
- 独立包启动 smoke 通过，47 个 Mach-O 均为 arm64，递归签名检查通过；匹配 dSYM UUID 见 15-uuids.log。
- 已知原天义音效资源异常未重测也未宣称修复；八人 ASan 长局超时、双机 LAN/长期稳定性仍沿用首版未完成项。
